# Паспорт проекта

## 1. Название проекта

 Например: «Магазин обуви „Fr33r“» 

## 2. Проблема

 У небольшого магазина обуви каталог ведётся на бумаге и в Excel: клиент не может посмотреть товар и оформить заказ, а продавец путается в остатках и не видит актуального наличия. 

## 3. Пользователи

. клиент магазина — просматривает каталог, ищет товар по фильтрам и оформляет заказ;
· продавец-консультант — ведёт каталог, обновляет остатки и меняет статусы заказов;
· администратор — управляет пользователями, ролями и правами доступа. 

## 4. Цель проекта

 Дать клиенту возможность выбрать товар и оформить заказ онлайн, а продавцу — видеть актуальные остатки в единой базе данных. 

## 5. Метрики успеха
· время оформления заказа — < 2 минут;
· клиент находит нужный товар через поиск/фильтры — за < 3 кликов;
· остатки в БД обновляются сразу после продажи, без ручного ввода;
· ошибки при вводе заказа — < 5% (валидация на стороне C#).

## 7. Риски

· не успеем с метриками к дедлайну → приоритизация: сначала каталог и заказ, метрики в конце;
· сложно придумать 30+ товаров → берём реальный ассортимент из открытых источников;
· проблемы с подключением MySQL на разных машинах команды → прописываем строку подключения в appsettings.json и не пушим её в GitHub;
· расхождение версий .NET у участников → фиксируем версию в global.json и README.
